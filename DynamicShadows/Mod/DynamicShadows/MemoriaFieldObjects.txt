# Per-map custom objects. Re-read on every field load: to try out positions it is
# enough to leave the map and walk back in, with no rebuild.
#
# Format:  <fldMapNo> <model> <x> <y> <z> [scale] [LIT]
#   LIT      drawn by the derived perspective camera, with the Standard shader,
#            real light and shadows. Without LIT it uses the game's PSX projection.
#   Models:  GEO_NPC_F0_CUB (our own FBX, 100 units at scale 1)
#            PRIMITIVE_CUBE / PRIMITIVE_PLANE (Unity primitives)
#   A '@' in front of the X makes the coordinates relative to bgi.charPos (careful,
#   that is not the entry point; on map 150 it is (-1423,0,1347) and you walk in Z 23..430)
#
# Global settings:
#   SCENESCALE <factor>                             field units per scene unit
#       The game works at ~340 units per metre (Steiner is about 593 tall), which
#       breaks every Unity setting that goes "per unit": lightmap resolution,
#       shadow distance, particle size, LOD. Modelling in metres and scaling here
#       brings those defaults back into a usable range.
#       It only affects SCENEBUNDLE content; LIT objects and the player proxy stay
#       in field coordinates.
#   SCENEBUNDLE auto                                one scene per map, by convention
#       Loads <fldMapNo>.unity3d on every map that has one. The file name IS the
#       configuration, so adding a map means dropping its bundle into the mod
#       folder: nothing to edit here. With no bundle the map plays normally and
#       the log says so.
#   SCENEBUNDLE <map> <file> [scene]                one specific scene, for exceptions
#       The bundle is looked up in the game root and in every active mod folder.
#       Without a scene name the first one in the bundle is used.
#       It brings its own lightmaps and light probes; its lights are restricted to
#       the 3D layer and any cameras it carries are stripped.
#   AMBIENT <r> <g> <b> [intensity]                 ambient light (0-1 per channel)
#       With the scenery baked in Blender, ambient carries the albedo and the
#       directional is turned down: that one is only there for the character and
#       their shadow. The map's tint shows up in the player DUMP, in _Color.
#   LIGHT <eulerX> <eulerY> <eulerZ> [intensity]    directional light of the 3D pass
#   SHADOWDISTANCE auto | <units>                   how far shadows reach
#       "auto" measures it on every map: twice the distance from the camera to the
#       furthest thing it has to cast onto. A fixed number cannot work for all of
#       them, because the camera is 3000 units from the player on one map and 6400
#       on another, and whatever falls outside the limit simply does not cast -with
#       no warning, and with the geometry, the lights and the shader all perfect.
#   PLAYER3D off|shadow|full|only                   puts the character into the 3D pass
#       shadow: still drawn with PSX but casts a real shadow
#       full:   also redrawn in the 3D pass (will look doubled over the PSX one)
#       only:   the character's PSX render is turned off and only the 3D pass one
#               remains, sharing a real z-buffer with the 3D geometry
#   CHARLIGHT <gain>                                how much light characters receive
#       Applied by tinting the material the game already draws them with: their
#       shader computes tex * (vertexColour * _Color), so multiplying _Color is the
#       control it already understands. They keep their colours, their alpha cutout
#       and their ordering against everything else, and only darken or take on the
#       hue of a nearby light. It is one colour per character, not per pixel; for
#       FFIX's flat models that is the correct resolution.
#       It is a gain on the DEVIATION from normal, and it has no ceiling: 0 leaves
#       them identical to the game, 1 applies the light exactly as the scene
#       computes it, and above 1 exaggerates it. That is the only control: the
#       lights stay however they are in the Unity scene, and this decides how much
#       of them reaches the character.
#       Darkening in shadow needs COLLIDERS on the scene geometry: the shadow is
#       resolved with a raycast because the shadow map cannot be queried from
#       script. The log warns when there are none.
#       Point lights tint without needing colliders.
#
# Diagnostic keywords:
#   MASKDEBUG [on|off]  paints the character proxy green, over the game's render.
#           It separates two faults that look identical on screen: if the green
#           spills outside their silhouette the mask does not match; if it fits
#           exactly, the mask is fine and the problem is the shadow.
#   SHADOWBIAS <bias> [normalBias]  shadow bias of the 3D pass lights.
#           Unity expresses it relative to the shadow map texel, so it grows with
#           SHADOWDISTANCE: at the distances a field needs, the default (0.05 /
#           0.4) becomes enormous in world units and the shadow detaches from the
#           feet. Try 0.01 0.1.
#   TRACE   player position in Memoria.log while walking
#   DUMP    renderers and materials of what was spawned and of the player
#   CAMERA  compares the PSX projection with the derived camera's
#   PROBE   shaders and shadow capabilities available in this build
#
# EXPORTSCENE  dumps the current map into MemoriaSceneExport/<map>/ with the camera
#              (field.json), the clean background (background.png) and the collision
#              mesh (walkmesh.obj). Then, to build the Blender project:
#                blender --background --factory-startup ^
#                  --python DynamicShadows/Tools/blender/build_field_project.py -- ^
#                  "<game path>/MemoriaSceneExport/150"
#
# Y axis: in field coordinates +Y is UP (confirmed by charAimHeight, which is added
# to raise the aim point, and by TRACE while climbing stairs). At Y=0 the object
# sits centred on the floor; raise the value to lift it.
#
# Cast. Alex./Guard = map 150

TRACE
CAMERA
EXPORTSCENE
SHADOWDISTANCE auto
AMBIENT 0.15 0.15 0.13 1.0
MASKDEBUG off
# Diagnostics for the catcher's additive light pass.
#   1 flat red, 2 shadow only (black where the light is blocked),
#   3 reach only (black where the lamp does not arrive), 4 the final factor,
#   off to turn it off.
CATCHERDEBUG off

# With SCENEBUNDLE the directional comes from the scene, and the loader restricts
# its cullingMask to the 3D layer, so it lights the character too. Leaving LIGHT
# active here would add a second directional on top. Only used without a bundle.
# LIGHT 50 -30 0 0.6
# Shadow catcher test: the character is still drawn by the game with its usual PSX render, and all
# the 3D pass contributes is their silhouette in the shadow map. That way the background and the
# character are untouched and the only new thing on screen is the shadow.
PLAYER3D shadow

# The single character-lighting control. In a normal area it changes nothing whatever its value;
# it only amplifies deviations: walking into shadow, or up to a flame. Raise or lower this number
# and that is all. The lights stay however they are in the scene.
CHARLIGHT 1.0
# Milestone 3, once the shadow is right: PLAYER3D only + CHARLIGHT 0 has to look
# IDENTICAL to the game's render.
# CHARLIGHT 0

# These two now come from the bundle at the same coordinates: leaving them active
# would overlap the ones in the scene and you would not know which you are seeing.
# 150 PRIMITIVE_PLANE -700 0 200 120.0 LIT
# 150 PRIMITIVE_CUBE  -700 80 500 80.0 LIT

# Unity scene, modelled in metres. A field position P goes into Unity at P/345
# (TRACE already gives you both figures).
#
# The 345 is NOT eyeballed: FF9BattleDBHeightAndRadius gives each model's height,
# and Steiner's (GEO_MAIN_F0_STN, id 5489) is 603 field units.
#     factor = 603 / height_in_metres    ->    603 / 1.75 = 345
# The only debatable part is what height to assign: 1.70 -> 355, 1.80 -> 335.
SCENESCALE 345
SCENEBUNDLE auto
